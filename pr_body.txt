💡 **What:**
Replaced the custom `retryFetch` logic which utilized a manual `for` loop and delays for handling fetch errors with `@tanstack/react-query`'s native caching, deduplication, and retry properties (`retry: 3`, `retryDelay: 1000`).

🎯 **Why:**
The previous implementation used custom retry loops per hook instance. By shifting to React Query's native retry mechanisms, we:
- Remove manual logic to reduce potential bugs and boilerplate code.
- Provide more native integration into React Query's event loop and state management.
- Remove redundant state logic that can block or overlap incorrectly with other React Query lifecycles.

📊 **Measured Improvement:**
As a client-side network request orchestration change, numerical benchmarks (like CPU instructions or memory usage in Node) do not neatly translate to browser runtime behavior where the primary bottleneck is I/O wait time. However, this is a distinct architectural optimization: removing a redundant custom abstraction wrapper (`retryFetch`) in favor of utilizing the optimized library's built-in robust caching, deduplication, and retry logic. This reduces bundle payload, removes loop overhead, and eliminates an imperative wrapper within a declarative React hook lifecycle.
